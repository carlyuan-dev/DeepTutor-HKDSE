# 三科学习工具链设计

## 目标与范围

在现有聊天 Agent 工具循环内，将数学客观题学习链扩展到中文、英文、数学。流程为读取分科学习记录、讲解或生成练习、等待作答、服务端评分、更新分科记录。通用聊天不受学科限制。

仅支持四选一客观题。中文支持字词、修辞、短篇阅读；英文支持词汇、语法、短篇阅读；数学保留现有能力。作文、开放题和口语继续使用现有工作台，不纳入这次工具链。不新增多 Agent、跨进程任务恢复或自动知识库选择。

## 方案选择

采用共享学习服务加显式学科参数，复用现有用户归属、答案键管理、事务提交和交互等待机制。相比为每科复制一套工具与数据库，共享实现可以让去重和恢复规则保持一致；相比立即接入所有工作台题型，先做客观题能明确评分边界。

## 工具与接口

- 新工具使用通用名称：`get_learning_state`、`explain_learning_concept`、`create_learning_practice`、`submit_learning_answer`。
- 状态读取、讲解、出题接受规范学科值 `Mathematics`、`Chinese`、`English`。模型根据用户明确需求选择；需求不明时先追问，不猜测知识库学科。
- 新建练习和查询状态必须明确学科；旧数学调用保留默认数学兼容行为。现有数学工具保留为兼容包装，但不与新工具重复暴露给模型。
- 提交只接受服务端 attempt_id 和答案；学科、用户、答案键及成绩均从服务端记录确定，客户端不得覆盖。
- 同步检查工具注册、上下文参数注入、提示词、结果展示及原有 Market 数学调用，不能只替换工具名称。

## 状态与迁移

- 学习会话由“用户＋聊天会话”改为“用户＋聊天会话＋学科”。每个学科独立保留待答练习，切科不取消或覆盖另一科任务。
- 知识点成绩按“用户＋学科＋知识点 ID”隔离；读取薄弱项、最后成绩、默认主题和待答练习都使用相同学科范围。
- 为中文、英文设置独立的默认知识点及别名。未知中文知识点不得全部归入同一个 `unmapped:unknown`；使用稳定、可区分的标识。
- 迁移在事务中进行，已有单科记录归为数学，保留会话和练习 ID、答案、成绩与事件。重复启动不得重复迁移或累计成绩。迁移失败回滚，不以清空数据库解决。
- 不修改用户原始开发数据；先在数据库副本和隔离测试库验证迁移。正式运行前保留数据库备份。

## 出题与阅读材料

- 共用结构校验和确定性评分，按学科调整提示词、默认主题、检索查询与讲解内容。
- 不强行复用工作台 HTTP 接口；优先复用适合的服务逻辑，避免把混合题型的生成结果直接塞入四选一评分器。
- 阅读练习将原文作为服务端保存的题目材料，返回给交互作答界面并在续答时保留；标准答案与解析在提交前不公开。
- 校验题目数量、四个选项、合法答案键和必要阅读原文。格式不合法不落库。模型生成的答案键仍可能有误，确定性评分不等于答案正确性保证。
- 知识库仅从用户已挂载范围使用。保持原有检索失败降级信息，不宣称无资料时也获得检索支持。

## 失败与恢复边界

- 同一练习重复提交相同答案返回已有结果，不重复计分；不同答案复用已提交标识沿用明确拒绝规则。
- 并发出题不得在同一学科学习会话产生多个待答练习；跨学科练习相互独立。
- 生成失败不写入半成品；建议生成失败不撤销已完成评分。
- 保留现有同进程断线续答，不宣称恢复整个 Agent 执行栈。切科后仍须按正确 attempt_id 回答原题。

## 核心验收

1. 中、英、数各跑通一次真实模型工具链，保存调用顺序和评分后重新读取的状态；统一使用已配置的 deepseek-flash，不输出凭据。
2. 模拟测试覆盖同会话跨学科状态隔离、阅读原文在作答与恢复时可见、答案键提交前不可见。
3. 验证重复/并发提交与用户归属，不重复计分或串用户。
4. 以旧版数据库样本验证迁移后数学记录和待答练习保留，重复初始化无副作用。
5. 原数学核心回归及必要前端交互检查通过；不增加无关的大规模评测或零碎测试。
